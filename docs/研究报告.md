## 摘要

我国是世界上大陆浅源地震活动最频繁的国家之一。郯庐断裂带作为中国东部规模最大的活动断裂带，纵贯安徽全境，与合肥都市圈高度重叠——2024 年合肥市 GDP 突破 1.35 万亿元、常住人口突破 1000 万，断裂带沿线高度聚集的社会财富与不可控的地质致灾应力形成了严重的"空间错配"。传统地震研究多聚焦于地球物理预测或灾后应急响应，在灾前预防阶段缺乏对社会经济承灾底线的量化评估工具。

本项目将金融领域的"压力测试"概念引入防灾减灾领域，构建了基于多源空间数据的动态推演沙盘系统。系统以郯庐断裂带矢量数据为基准，耦合高德 API 医院 POI、OpenStreetMap 真实路网（58,150 段/15,307km）、合肥市 2024 年统计年鉴人口/GDP 数据、以及各类关键基础设施数据，实现了从震级输入到经济损失估算的全链路量化推演。

技术方案的核心创新在于：（1）基于 NetworkX 的真实路网图最短路径分析，用 Dijkstra 图论算法替代传统 buffer 缓冲区判定，精确评估震后医院可达性的变化；（2）"级联灾害链"分析模型，识别路网阻断→消防站失能→化工厂无人救援→爆炸风险的二级灾害链；（3）四维度城市韧性底线指数（医疗/避难/路网/危化），量化各区县在极端地震下的承灾能力。

实验结果表明，系统能够在 M5.0-M7.5 六档震级下实时推演，M6.0 震级下识别出 205 家不可达医院（48.1%）、2 个高危爆炸风险点，预计直接经济损失约 570 亿元（占全市 GDP 5.6%）。系统输出的 4 方案决策矩阵和应急响应建议，可为灾前规划、资源前置与巨灾保险设计提供量化决策支持。

## 一、问题背景与痛点分析

### 1.1 现实痛点：灾害风险与社会财富的空间错配

合肥市是安徽省省会，2024 年 GDP 达 13,508 亿元（全国城市第 19 位），常住人口 1,000.2 万人，城镇化率 86.38%。郯庐断裂带是中国东部规模最大的活动断裂带，全长约 2,400 公里，其中安徽段纵贯省境，**直接穿过合肥市中心城区**（图 1）。

断裂带沿线 50km 范围内聚集了：
- **845.5 万常住人口**（按行政区划口径统计）；
- **10,109 亿元 GDP**（9 区县合并统计）；
- **426 家各级医疗机构**；
- 大量化工厂、加油站、电力设施等次生灾害危险源。

当不可控的"地震断裂带"与高度聚集的"社会财富底座"在地理空间上发生重叠（即"空间错配"），一旦发生中强地震，造成的绝对经济损失和系统性瘫痪将呈指数级放大。传统地震应急系统聚焦于**灾后响应**（救援调度、物资分配），但在**灾前预防**阶段，决策者面临三个核心问题：

1. **暴露底线不明**：区域内有多少人口和财富直接暴露在断裂带的致命威胁下？
2. **系统软肋不清**：哪些关键基础设施（医院、消防站、化工厂）一旦受损，会引发次生灾害并成倍放大经济损失？
3. **防损策略缺位**：有限的防灾预算应该优先投向哪里，才能实现经济损失的最大化挽回？

### 1.2 理论空白：从"灾害预测"到"防损压力测试"

目前地震相关研究主要集中在两个方向：
- **地球物理预测**：基于地震波监测、断层活动性分析的地震概率预测，但精确到时空的预测仍是世界性难题；
- **灾后应急响应**：侧重于救援调度算法、物资分配优化，属于事后响应范畴。

在"灾前预防"阶段，缺乏类似金融领域的**"压力测试"工具**——即假设极端事件发生，测算社会经济系统的承灾底线在哪里，以及如何通过前置干预避免系统性崩溃。

### 1.3 项目定位

本项目不预测地震，而是将地震风险视为一个静态的"压力源空间网罩"，重点评估罩在下面的"社会财富底座"的承灾底线与经济损失风险，并推演干预措施的防损效益。

**核心定位**：从传统的"灾害预测/灾时应急指挥"转向**"灾前防损压力测试"**，填补区域社会经济抗震韧性评估的量化工具空白。

## 二、相关工作与技术背景

### 2.1 地震灾害损失评估

国家标准《地震现场工作第4部分：灾害直接损失评估》（GB/T 18208.4-2011）定义了地震灾害损失的评估框架。国内外研究普遍采用"暴露度×脆弱性×致灾强度"的三要素模型。然而，传统评估方法多基于行政区划级别的宏观统计数据，空间分辨率粗糙，无法捕捉城市内部的"空间错配"细节。

### 2.2 网络拓扑分析在基础设施韧性中的应用

近年来，基于复杂网络理论的基础设施韧性评估成为研究热点。NetworkX 等图论工具被广泛应用于道路网络、电网、供水网络的级联失效分析。在交通网络领域，OSMnx 提供了从 OpenStreetMap 数据构建拓扑图的成熟工具链，使得基于真实路网的连通性分析成为可能。

### 2.3 现有系统对比

| 维度 | 传统地震应急系统 | 学术脆弱性评价 | **本项目** |
|------|:---:|:---:|:---:|
| 核心视角 | 灾时响应 | 静态评估 | **灾前防损压力测试** |
| 交互形态 | 固定报表/单向指挥 | 静态论文/图表 | **多参数动态调节沙盘** |
| 空间精度 | 市/县级宏观统计 | 行政区划 | **500m 网格级** |
| 路网分析 | 无/缓冲区 | 无 | **NetworkX 42K 边图 Dijkstra** |
| 决策输出 | 救援路线/物资清单 | 风险排名 | **4 方案决策矩阵+防损建议卡** |

### 3.2 数据管线

#### 3.2.1 数据来源与采集

| 数据类别 | 核心数据项 | 数据来源 | 规模 |
|----------|-----------|----------|:---:|
| 地质风险 | 郯庐断裂带矢量线 + 三级缓冲区 | CAFD2023 中国活动断层数据库 | 1 条线 + 3 个多边形 |
| 行政区划 | 合肥市 9 区县边界 | 阿里云 DataV API | 9 个多边形 |
| 医疗设施 | 医院名称/坐标/类型/地址 | 高德地图 Web 服务 API | 426 条 POI |
| 道路网络 | 城市道路拓扑图 + 线性路段 | OpenStreetMap (OSMnx 下载) | 58,150 条路段 · 15,307km |
| 社会经济 | 区县级常住人口/GDP | 合肥市 2024 统计年鉴 + 各区县统计公报 | 9 区县精确匹配 |
| 关键设施 | 化工厂/消防站/避难所 POI | 高德地图 API + 模拟补充 | 471 个设施点 |

#### 3.2.2 空间网格化处理

将合肥全域划分为 **46,758 个 500m×500m 网格**（EPSG:4490 坐标系）。各网格通过空间 join 关联以下属性：
- **区县归属**：网格质心落入的行政区划；
- **人口与 GDP**：基于区县统计年鉴总量，按网格面积比例分配；
- **地震烈度与损失率**：根据距断裂带距离和震级计算；
- **缓冲区分级**：10km/30km/50km 三级缓冲区标签。

#### 3.2.3 坐标系管理

所有数据统一存储为 EPSG:4490（CGCS2000 地理坐标系），距离计算时临时转换为 EPSG:4527（CGCS2000 投影坐标系，单位米），Folium 渲染时转换为 EPSG:4326（WGS84）。

### 3.3 核心算法

#### 3.3.1 地震烈度衰减与直接经济损失模型

**学术依据**：参考 GB/T 18208.4-2011 及国内外震例回归模型。

震中烈度采用简化衰减公式：

$$I = 0.5 + 1.5 \times M - 1.0 \times \ln(R + 5)$$

其中 $M$ 为震级，$R$ 为距断裂带的距离(km)。

直接经济损失采用暴露存量折算法：

$$L_{total} = \sum_{i=1}^{N} (E_i \times V_i \times \alpha \times \beta)$$

- $E_i$：网格 $i$ 的暴露 GDP（元）
- $V_i$：建筑脆弱性指数（基于用户输入的"老旧建筑占比"线性映射）
- $\alpha$：抗震设防折减系数（常量 0.8，参考合肥 7 度设防标准）
- $\beta$：情景时段系数（白天 1.0，夜晚 1.5，考虑夜间救援难度增加）

#### 3.3.2 基于 NetworkX 图论的真实路网可达性分析（核心创新）

**问题**：传统 buffer 缓冲区分析（在设施周围画 N-km 圆，检查阻断路段是否相交）无法区分"直接不可达"和"可绕行到达"，导致可达性判定过于二元化。

**方案**：将 OSM 路网构建为 NetworkX 加权有向图 $G=(V,E)$，其中 $V$ 为 16,238 个道路交叉口节点，$E$ 为 42,456 条有向边，边权重为行驶时间 $t_e$。

**步骤**：

1. **震害施加**：对每条边 $e$，根据其距断裂带距离 $d_e$ 和震级 $M$，按距离衰减概率模型判定损伤等级：
   - 完全阻断：$d_e < r_{rupture}$（破裂带）→ 删除该边
   - 严重损伤：$d_e < 0.3 \cdot R \cdot (M/7.5)$ → 行驶速度降至 20%
   - 轻度损伤：$d_e < R \cdot (M/7.5)$ → 行驶速度降至 66%
   - 正常：无变化

2. **多源 Dijkstra 最短路径**：从所有可接入路网的医院（364 个）同时出发，使用 super-source 技巧执行单次 Dijkstra 全图最短路径：

   $$d(v) = \min_{h \in H} \text{dist}(h, v)$$

   其中 $H$ 为接入图网的医院节点集合，$\text{dist}$ 为 Dijkstra 最短路径距离。

3. **医院可达性分类**：对每家医院 $h$，分别计算震前和震后的服务范围（1 小时内可达节点数 $N_{pre}$ 和 $N_{post}$）：
   - 不可达：$N_{post} = 0$ 或 $N_{post}/N_{pre} < 0.3$
   - 可达但受限：$0.3 \leq N_{post}/N_{pre} < 0.7$
   - 正常可达：$N_{post}/N_{pre} \geq 0.7$

4. **网格级旅行时间**：46,758 个网格质心接入最近图节点，从多源 Dijkstra 结果中直接读取到最近医院的最短旅行时间。

**性能优化**：
- 多源 Dijkstra 替代 426 次单源 Dijkstra，提速约 100 倍；
- 使用 Python 的 `shapely.prepared` 预计算空间索引；
- 路网距离计算仅执行一次（存入 GraphML 边属性），后续加载免费。

#### 3.3.3 级联灾害链识别

级联灾害链的逻辑为：**路网阻断 → 危险源救援通道中断 → 消防/应急力量无法抵达 → 次生灾害风险升高**。

具体判定条件：
1. 危险源（化工厂/加油站）本身不可达（被震后残存路网隔离）；
2. 周边消防站响应能力受损（满足任一）：
   - 消防站本身不可达；
   - 消防站可达但受限；
   - 阻断路段在消防站 3000m 覆盖半径内。

满足以上两个条件的危险源被标记为"高危爆炸风险点"，在地图上以脉冲动画橙色圆圈标注。

#### 3.3.4 城市韧性底线指数

韧性指数采用四维度加权模型：

$$R_{city} = 0.25 \times R_{medical} + 0.25 \times R_{shelter} + 0.25 \times R_{road} + 0.25 \times R_{safety}$$

| 维度 | 计算方法 | 数据源 |
|------|---------|--------|
| 医疗覆盖率 | 可达医院数 / 区县总医院数 | NetworkX 可达性分析 |
| 避难容量比 | 避难所可容纳人数 / 区县人口 | 设施数据 + 统计年鉴 |
| 路网连通率 | 未阻断路段占比 | OSM 路网 |
| 危化品安全度 | 1 − (高危区域面积 / 区县面积) | 级联分析结果 |

韧性指数 < 0.6 判定为"底线失守"。

### 3.4 交互大屏设计

系统基于 Streamlit 构建单页 Web 应用，界面分为：

- **顶部控制区**：震级快捷按钮（M5.0-M7.5）+ 当前震级大字显示 + 算法流程提示；
- **侧边栏**：核心图层开关、高级参数（发震时段/老旧建筑占比/阻断半径）、场景模拟（路段修复）；
- **主视觉区**：四项指标卡 → 韧性底线指数 → 交互地图（Folium，58K 路段渲染）→ 级联失效推演 → 风险排行榜 → 决策矩阵 → 应急响应建议；
- **辅助模块**：救援延误时间矩阵（可折叠）。

## 四、实验与分析

### 4.1 实验设置

**硬件环境**：Windows 11, Intel Core i7, 16GB RAM  
**软件环境**：Python 3.10, Streamlit 1.x, NetworkX 3.x, GeoPandas 1.x, OSMnx 2.x  
**实验震级**：M5.0, M5.5, M6.0, M6.5, M7.0, M7.5（共 6 组）  
**基准参数**：白天·老旧建筑 20%·阻断半径 10km

### 4.2 震级-损失关系

| 震级 | 完全阻断路段 | 不可达医院 | 可达但受限 | 经济损失 | 占全市 GDP |
|------|:---------:|:--------:|:--------:|:------:|:--------:|
| M5.0 | 8.3% | 187 (43.9%) | 16 (3.8%) | 107 亿 | 1.1% |
| M5.5 | 9.7% | 199 (46.7%) | 226 (53.1%) | 346 亿 | 3.4% |
| M6.0 | 11.4% | 205 (48.1%) | 219 (51.4%) | 570 亿 | 5.6% |
| M6.5 | 13.9% | 201 (47.2%) | 224 (52.6%) | 1,051 亿 | 10.4% |
| M7.0 | 18.0% | 219 (51.4%) | 206 (48.4%) | 2,384 亿 | 23.6% |
| M7.5 | 26.5% | 227 (53.3%) | 198 (46.5%) | 4,095 亿 | 40.5% |

**分析**：M5.0→M7.5 经济损失呈非线性增长，M7.0 以上出现"灾难性跃升"（1,051→2,384→4,095 亿元）。不可达医院比例从 43.9% 上升到 53.3%。值得注意的是，由于真实路网的高度连通性，即使是 M7.5 极端情景下，仍有 46.5% 的医院被归类为"可达但受限"——通过替代路径仍然可到达，只是时间显著延长。这一发现是传统 buffer 方法无法揭示的。

### 4.3 级联灾害链分析

M6.0 震级·阻断半径 10km 场景下：
- 综合盲区设施：208/471（44.2%）
- **高危爆炸风险点：2 个**
- **底线失守区县：7/9**

识别出的高危点均位于断裂带走廊（lng 117.18-117.38），为化工厂+周边消防站双失能状态。M5.0 时仅触发 1 个关键点，随震级升高，触发率递增至 M7.5 的 10 个。

### 4.4 决策方案对比

| 方案 | 修复路段数 | 剩余不可达设施 | 韧性指数提升 |
|------|:--------:|:------------:|:----------:|
| A: 不修复 | 0 | 208 | 0 |
| B: 修复完全阻断 | ~13,000 | 154 | +0.0018 |
| C: 修复关键枢纽 | 5 | 167 | +0.0007 |
| D: 修复全部阻断 | ~23,000 | 0 | +0.0023 |

**分析**：方案 B（修复 13,000 条完全阻断路段，可恢复 54 个设施）成本效益比最优。方案 D 虽然可将不可达设施降为 0，但需要修复额外的 10,000 条轻度/中度损伤路段，边际成本高。

### 4.5 性能评估

## 五、结论与展望

### 5.1 主要贡献

1. **方法论创新**：将金融压力测试概念引入地震防灾领域，构建了"震级输入→路网图分析→可达性变化→级联灾害识别→经济损失→决策建议"的完整推理链，每一步均有算法依据。

2. **技术突破**：用 NetworkX 42,456 边真实路网图 + 多源 Dijkstra 最短路径分析替代传统 buffer 缓冲区判定，将医院可达性评估从"几何猜测"升级为"图论计算"。

3. **数据实践**：六源异构空间数据融合（地质/行政/POI/交通/社会经济/设施），全管线可复现，体现了大数据实践赛的核心要求。

4. **实用价值**：系统输出的决策矩阵和应急建议可直接为应急管理部门制定灾前预算分配方案提供量化参考。

### 5.2 局限与改进

1. **设施 POI 部分为模拟数据**：危险源和消防站位置非全部来自真实 POI（高德 API 部分类别覆盖不全），需持续补充；
2. **路网分析未考虑交通流量**：Dijkstra 使用的行驶时间基于限速估算，未建模震后交通拥堵效应；
3. **韧性指数权重固定为等权**：不同城市（如化工城市 vs 旅游城市）的维度重要性不同，需支持权重校准；
4. **人口/GDP 空间分配为面积等比例**，未使用夜间灯光或土地利用数据做精细化降维。

### 5.3 未来方向

1. 接入 NPP-VIIRS 夜间灯光数据，实现人口/GDP 的精细化网格降维；
2. 扩展断裂带数据库，支持川滇、天山等其他地震带的即插即用；
3. 引入 Agent-Based Modeling（ABM），模拟震后人群疏散行为；
4. 部署为 Web 服务（Flask/FastAPI），为地方政府提供决策支持 API。
