## 阶段一：重写损失计算算法

### 1.1 目标

替换当前无意义的 `医院数 × 损失率` 算法，实现基于网格人口和GDP的真实损失计算。

### 1.2 当前问题代码

文件：`src/generate_scenarios.py`，第50-59行和第198-225行

```python
# 当前损失率函数（保留，可复用）
def loss_rate(i):
    if i < 5: return 0.0
    elif i < 7: return 0.05
    elif i < 8: return 0.20
    else: return 0.50

# 当前错误的损失计算（需删除重写）
grid_w["grid_loss"] = grid_w["hospital_count"] * grid_w["loss_rate"]  # 无意义
summary["estimated_loss"] = summary["total_grid_loss"]  # 无意义
```

### 1.3 新算法设计

创建新文件：`src/step8_loss_recalculation.py`

```python
"""
重写损失计算：基于网格人口和GDP的真实损失估算
输入：
  - grid_base.geojson（静态网格，含district标签）
  - grid_intensity_M{X}.csv（每个震级的烈度）
  - population_gdp_summary.csv（9区县人口GDP汇总）
  - NPP-VIIRS夜间灯光数据（如果可用，否则用面积加权回退）
输出：
  - loss_estimate_M{X}.csv（重写后的损失估算）
  - exposure_summary_M{X}.csv（暴露人口/经济汇总）

算法：
  1. 人口/GDP空间分配：
     - 优先方案：用NPP-VIIRS夜间灯光数据将区县人口GDP分配到网格
     - 回退方案：按网格面积占比分配区县人口GDP
  2. 暴露人口计算：
     exposed_population = grid_population × loss_rate(intensity)
  3. 经济损失计算：
     economic_loss = grid_gdp × loss_rate(intensity)
  4. 汇总到区县级：
     按district分组求和
```

### 1.4 具体步骤

1. 读取 `population_gdp_summary.csv`，获取9区县人口和GDP
2. 读取 `grid_base.geojson`，获取每个网格的面积和区县归属
3. 按区县分组，将人口和GDP按网格面积占比分配到各网格
   - 如果后续有夜间灯光数据，则按灯光亮度比例分配
4. 对每个震级M{X}：
   - 读取 `grid_intensity_M{X}.csv`
   - 合并网格人口和烈度
   - 计算 `exposed_pop = grid_pop × loss_rate(intensity)`
   - 计算 `economic_loss = grid_gdp × loss_rate(intensity)`
   - 按区县汇总：暴露人口、经济损失、平均烈度
   - 输出 `loss_estimate_M{X}.csv`
5. 输出暴露汇总 `exposure_summary_M{X}.csv`

### 1.5 输出格式

`loss_estimate_M{X}.csv`：
```
district,total_population,exposed_population,total_gdp,economic_loss,avg_intensity,pop_loss_rate,gdp_loss_rate
包河区,1342000,892000,1902.9,95.1,6.09,0.665,0.050
```

### 1.6 验证方法

```python
# 验证脚本（写在step8末尾）
# 1. 检查各区县人口之和 = 总人口845.5万
# 2. 检查M7.5的暴露人口 > M5.0的暴露人口
# 3. 检查经济损失随震级单调递增
# 4. 检查无NaN值
```

## 阶段二：统一可达性算法

### 2.1 目标

将消防站、避难所、危险源的可达性计算从缓冲区方法升级为 NetworkX 图论方法，与医院保持一致。

### 2.2 当前问题

- 医院可达性：用 NetworkX multi-source Dijkstra（`src/network_analysis.py`）
- 其他设施可达性：用缓冲区相交判断（`src/step7_cascade_analysis.py` 的 `_check_accessibility`）
- 两种方法结果不可比

### 2.3 具体步骤

创建新文件：`src/step9_unified_accessibility.py`

1. 读取 `hefei_road_graph.graphml`（已有路网图）
2. 读取三类设施坐标：
   - `facilities_hazards.geojson`
   - `facilities_rescue.geojson`
   - `facilities_shelters.geojson`
3. 对每个震级M{X}：
   - 读取 `road_blocked_M{X}.geojson`
   - 从路网图中移除"完全阻断"的路段
   - 给"严重损伤"路段的权重乘以惩罚系数（如3倍）
   - 对每类设施的每个点：
     - 找到最近的路网节点
     - 用 multi-source Dijkstra 计算从所有医院/消防站到该点的最短路径
     - 如果不可达 → "不可达"
     - 如果最短路径时间 > 阈值（如30分钟） → "可达但受限"
     - 否则 → "正常可达"
4. 输出 `accessibility_facilities_M{X}.csv`

### 2.4 输出格式

`accessibility_facilities_M{X}.csv`：
```
name,type,district,accessibility,travel_time_min,dist_to_fault_km
合肥市消防救援支队特勤一站,消防站,蜀山区,不可达,999,8.5
```

### 2.5 验证方法

```python
# 1. 检查M5.0时不可达数量 < M7.5时不可达数量
# 2. 检查消防站可达性分布合理（断裂带附近的更易不可达）
# 3. 与医院可达性结果交叉验证（同一区域趋势一致）
```

## 阶段三：实现崩溃临界点识别

### 3.1 目标

这是项目核心创新点。对每个震级计算四个系统的功能损失率，找出系统崩溃的临界震级。

### 3.2 算法设计

创建新文件：`src/step10_collapse_threshold.py`

四个系统的崩溃判定：

| 系统 | 指标 | 崩溃阈值 | 数据来源 |
|------|------|---------|---------|
| 医疗系统 | 可达医院比例 | < 30% | accessibility_M{X}.csv |
| 救援系统 | 可达消防站比例 | < 40% | accessibility_facilities_M{X}.csv |
| 交通系统 | 路网连通度 | < 0.5 | road_blocked_M{X}.geojson + graph |
| 避难系统 | 避难容量/需转移人口 | < 0.3 | facilities_shelters + exposure_summary |

### 3.3 具体步骤

1. 对每个震级M{X}：
   - **医疗系统功能率** = 正常可达医院数 + 0.5×受限医院数 / 总医院数
   - **救援系统功能率** = 正常可达消防站数 + 0.5×受限消防站数 / 总消防站数
   - **交通系统连通度** = 最大连通子图节点数 / 总节点数（用NetworkX计算）
   - **避难系统功能率** = 可达避难所总容量 / 需转移人口
2. 绘制四系统功能率随震级变化的曲线
3. 找出每个系统功能率跌破阈值的震级 → 该系统的崩溃临界点
4. 取四个系统中最早崩溃的震级 → 城市生命线系统崩溃临界点
5. 输出 `collapse_threshold.csv`

### 3.4 输出格式

`collapse_threshold.csv`：
```
magnitude,medical_ratio,rescue_ratio,transport_ratio,shelter_ratio,medical_collapse,rescue_collapse,transport_collapse,shelter_collapse,city_collapse
5.0,0.98,0.95,0.92,0.85,False,False,False,False,False
5.5,0.85,0.80,0.78,0.65,False,False,False,False,False
6.0,0.62,0.55,0.58,0.45,False,False,False,False,False
6.5,0.28,0.35,0.42,0.25,True,True,False,True,True
7.0,0.15,0.20,0.25,0.12,True,True,True,True,True
7.5,0.05,0.08,0.10,0.05,True,True,True,True,True
```

### 3.5 验证方法

```python
# 1. 所有功能率随震级单调递减
# 2. 崩溃判定一旦为True，更高震级也必须为True
# 3. 城市崩溃临界点 = 四系统中最早崩溃的震级
# 4. 检查临界点在M6.0~M7.0之间（符合合肥地质条件预期）
```

## 阶段五：引入夜间灯光数据

### 5.1 目标

用 NPP-VIIRS 夜间灯光数据将区县人口GDP分配到网格级，提高空间精度。

### 5.2 数据源

- NPP-VIIRS 月度合成夜间灯光数据
- 下载地址：NOAA NGDC（https://ngdc.noaa.gov/eog/viirs/download_utiles.html）
- 数据格式：GeoTIFF，分辨率约500m（与我们的网格一致）
- 需要下载合肥地区（经度116.5-118.0，纬度31.0-32.4）的数据

### 5.3 具体步骤

创建新文件：`src/step11_nightlight_population.py`

1. 下载 NPP-VIIRS 年度合成数据（2023或2024年）
2. 用 rasterio 读取 GeoTIFF
3. 将灯光数据重采样到与 grid_base.geojson 一致的网格
4. 对每个区县：
   - 统计该区县内所有网格的灯光亮度总和
   - 按灯光亮度比例分配区县人口到各网格
   - 按同样的方法分配GDP
5. 输出 `grid_population_gdp.csv`（每个网格的人口和GDP）
6. 用新数据重新运行阶段一的损失计算

### 5.4 回退方案

如果夜间灯光数据下载或处理困难，使用面积加权法：
- 每个网格人口 = 区县人口 × (网格面积 / 区县总面积)
- 每个网格GDP = 区县GDP × (网格面积 / 区县总面积)

### 5.5 验证方法

```python
# 1. 各区县网格人口之和 = 区县总人口
# 2. 城区网格人口密度 > 郊区网格人口密度
# 3. 夜间灯光高的网格人口 > 灯光低的网格人口
```

## 注意事项

1. **不要删除或覆盖原始数据文件**，特别是 `hefei_hospital.csv`（426家真实医院POI）和 `hefei_road_graph.graphml`（58K路段路网图）
2. **新脚本用新文件名**，不要直接修改现有脚本，便于回退
3. **每个脚本末尾必须有验证代码**，输出检查结果到控制台
4. **坐标系统一致**：地理坐标用 EPSG:4490，投影计算用 EPSG:4527
5. **随机种子固定**：所有涉及随机的代码用 `SEED = 42` 或 `SEED = 2026`，保证可复现
6. **输出编码**：CSV 文件用 `utf-8-sig` 编码，GeoJSON 用 `utf-8`
7. **如果某步失败**：记录错误信息，跳过该步继续执行后续步骤，最后统一处理失败项
8. **阶段间隔离**：每个阶段独立可运行，不依赖前序阶段的内存状态，只依赖文件输出
